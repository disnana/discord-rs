# 未確認・不明のもの

「未確認」は、**まだ確かめていない**という意味で、「問題がある」という意味ではありません。確認する方法と、誰が行うかを書いています。出典は `docs/progress.md`（2026-11-16 の節）と `docs/known-limitations.md` です。

## 「不明」の設計上の論点（調べ・決めるもの）

- コピーで作業してコミットする方式で、同じ状態を触る処理が同時に来たときの扱い（直列化か、衝突したら再試行か）。→ [02](02-copy-on-commit-state.md)
- Core の無停止差し替えで、「全体で 1 つの数」のような状態の引き渡しの方法。→ [03](03-core-hot-swap.md)
- 複数ホストで使う既存の部品の選択（OpenRaft か、etcd や Consul のような外部の仕組みか）。→ [04](04-multi-host-preparation.md)
- 利用者の状態（StateStore）が、本番でどこまで保存・復元できるか。→ [07](07-state-persistence.md)
