## 了承した内容

1. **基盤が持つ状態：** 重複排除の記憶（`SeenIds`）は、基盤の責任で新 Core に引き継ぐ。引き継ぎに失敗しても、更新は止めない（警告を出し、記憶が空の新 Core で続ける）。デモ状態（`!count`、`!job`）は、基盤の特別扱いをやめ、任意の引き継ぎフックを使う。
2. **止まったハンドラ：** 「診断を出し、運用者が管理操作で対処する」。段階は、P1（daemon から診断を照会）→ P2（閾値を設定可能に）→ P3（Core 単位の管理操作）。**自動の再起動・停止は保留**（DDR で未合意のまま）。最初に P1 に着手する。
3. **Core の無停止差し替え（`03`）：** DDR-0001 に合わせた骨子（準備 → 切り替え → 旧 Core の退役）。切り替え前の失敗は旧 Core で継続、切り替え後の失敗は切り戻さず通常の障害として扱う。`03-core-hot-swap.md` を、この内容で書き換えてよい。
4. **着手の順序（提案の「おすすめの順序」）：** (1) P1・P2、(2) `03` の書き換えと提案 1 の決定の反映、(3) Core の無停止差し替えの実装（シングルの完成後）、(4) P3。
