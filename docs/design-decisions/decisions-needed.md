# 判断が必要なもの（ユーザー向け）

「判断」とは、方針を決めてもらうことです。それぞれ、**私の推奨**を先頭に書いています。決まったら、このファイルの「決定」の欄を更新します。

## 優先して決めたいもの

### D1. 止まったハンドラ（B3）を、どこまで自動で対処するか
詳細：[01-stuck-handler.md](01-stuck-handler.md)、[02-copy-on-commit-state.md](02-copy-on-commit-state.md)

| 選択肢 | 内容 | 利点 | 欠点 |
|---|---|---|---|
| **a. 観測のみ（現状）** | 30 秒以上の要求を警告するだけ | 安全。実装済み | 自動では直らない。手動で Core を落とす |
| **b. 一定時間でその Core を自動再起動** | 例：120 秒止まったら Core を落とし、botd が再起動、最後に保存した状態に戻る | 実装が小さい。確実に復旧する | 中断された処理は「結果不明」になる。その Core の他の処理も巻き込まれる |
| **c. コピーで作業しコミットする方式（根本対応）** | 状態のコピーで処理し、最後に一括で書き戻す。止まったらコピーを捨てる | 状態が壊れない。止まった処理だけを打ち切れる | 設計と実装が大きい。同時に同じ状態を触る処理の衝突の扱いが要る |

**推奨：** 当面は a のまま、b を「設定で有効にできる任意の機能」として検討し、c は設計を書いて評価する。
**決めてほしいこと：** (1) 許容できる停止時間（何秒で「止まった」とするか）。(2) 結果不明になった処理の扱い（ユーザーへの通知の有無など）。(3) b を入れてよいか。

**決定：** （未）

### D2. 「シングルが完成した」と言える条件（完成の定義）
**推奨（案）：** 次がすべてそろったとき。
1. 最新版で、Oracle の放置が 6 時間以上で、再起動 0・メモリと fd の増加なし。
2. Oracle で OS 再起動後に、botd が自動で起動して Bot が応答する。
3. `!workers` の更新中の挙動を実機で確認（二重返信の有無）。
4. D1（B3 の方針）が決まり、実装されている。
5. 運用者ガイドが最新で、失敗時の見方が書かれている。
6. Interaction（スラッシュコマンド）の重複が起きないことを、実 Discord で 1 回確認。

**決めてほしいこと：** この条件でよいか、足す・外すものがあるか。

**決定：** （未）

### D3. 結果不明の外部操作の方針（再試行を許すか）
詳細：[08-unknown-outcome-operations.md](08-unknown-outcome-operations.md)
**推奨：** 現状（自動で再試行しない）を維持し、Discord の重複防止の印（nonce）が使えるか調査する。使えるなら、メッセージ作成だけ、安全に再試行する。
**決めてほしいこと：** 調査を進めてよいか。

**決定：** （未）
